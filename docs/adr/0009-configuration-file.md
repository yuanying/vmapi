# 0009. 設定はリポジトリの外の YAML ファイルで与える

- Date: 2026-10-30
- Status: Accepted

## Context

vmapi には、環境ごとに違う値がある。払い出す IP の範囲とネットワーク、ディスクの置き場、libvirt の接続先、管理者の名前、使える OS イメージの一覧である。イメージの一覧は項目が入れ子になり、コマンドラインのフラグには並べにくい。

IP の範囲や LAN の gateway は、公開してよい情報ではない。このリポジトリも、compose を置く dotfiles も public である。

## Decision

**設定は一つの YAML ファイルで与える。置き場は `~/.config/vmapi/config.yaml` で、このリポジトリにも dotfiles にも置かない。** コンテナにはこのファイルを読み出し専用でマウントし、`--config` でパスを渡す（[[0008]]）。`--config` を省いたときは `$XDG_CONFIG_HOME/vmapi/config.yaml`、`XDG_CONFIG_HOME` が無ければ `~/.config/vmapi/config.yaml` を読む。

項目と既定値は `docs/config.md` に書く。決まりは次のとおり。

- **環境ごとに違う値には既定値を与えない。** ディスクの置き場、ネットワーク、イメージの一覧が無ければ起動を拒否する。既定値を持つのは、どこで動かしても同じでよい値（待ち受けるアドレス、libvirt の接続先）だけである。
- **知らない項目があれば起動を拒否する。** 書き間違えた項目が黙って無視され、既定値で動くのを防ぐ。
- **検証は最初の誤りで止めず、見つかった誤りをすべて項目の名前を添えて報告する。** 範囲の始まりと終わりの順、範囲が gateway と同じサブネットに入っているか、gateway が範囲に入っていないか、イメージの名前の重複と形（VM の名前と同じ形、[[0003]]）、SHA-256 の形などを確かめる。
- **設定は起動のときに一度だけ読む。** 変えたら vmapi を再起動する。
- 設定の範囲を狭めても、すでに範囲の外になった IP を持つ VM はそのまま残る。新しく払い出さないだけである。

## Consequences

- 設定はホストの手元にしか無いので、失ったときに戻す手段は無い。項目は少ないので、`docs/config.md` を見て書き直せる。
- 範囲を決めるときは、既存の VM や LAN の機器の IP と重ならないことを人間が確かめる（[[0003]]）。
- 検証は設定の構造体の上の純関数にでき、テーブルテストで規則を並べて確かめられる。
