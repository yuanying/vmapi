# 0006. ディスクは qcow2 の overlay、スナップショットは内部スナップショットにする

- Date: 2026-10-30
- Status: Accepted

## Context

VM のディスクは、保管したイメージ（[[0004]]）から作る。既存のスクリプトはイメージを VM ごとにコピーしてから大きさを変えていた。イメージを backing file にした qcow2 の overlay にすれば、コピーの時間と容量が要らない。

スナップショットは、VM の状態をある時点に戻すために使う（Kubernetes のアップグレードを試す前の状態に戻す、など）。libvirt のスナップショットには、qcow2 の中に持つ内部スナップショットと、別のファイルを重ねる外部スナップショットがある。外部スナップショットは、復元と削除のときにファイルの付け替えを vmapi が管理しなければならない。

overlay とスナップショットを作る方法には、libvirt のストレージプールの API を使う方法と、`qemu-img` を呼ぶ方法がある。ストレージプールを使うには、ディスクの置き場をプールとして libvirt に定義しておく必要がある。

## Decision

### ディスク

- **VM のディスクは、保管したイメージを backing file にした qcow2 の overlay にする。** 大きさは作成のときに GiB で指定する。イメージの仮想的な大きさより小さい値は `400` で拒否する。
- **overlay は `qemu-img create` を外部のコマンドとして呼んで作る。** ストレージプールは定義しない。ディスクの置き場をプールにするホスト側の作業を増やさないためである。コマンドは seed ISO の `xorriso`（[[0005]]）と同じく、Go のインターフェイスの後ろに置き、vmapi のイメージに入れる。
- **ファイルの置き場は、設定のディスクの置き場（[[0009]]）の下に固定する。** イメージは `images/<sha256>.img`、VM のディスクは `vms/<名前>/disk.qcow2`、seed ISO は `vms/<名前>/seed.iso` とする。ドメイン定義と overlay の backing file にはこれらの絶対パスを書く。
- ドメイン定義は vmapi が組み立てる。ディスクと seed ISO のほかは、ブリッジ（設定の `br0`）につないだ virtio のネットワークインターフェイス（MAC は [[0005]]）とシリアルコンソールを持つ。呼ぶ側から XML やパスは受け取らない（[[0008]]）。

### スナップショット

- **スナップショットは libvirt の内部スナップショットにする。** qcow2 の overlay の中に持つ。
- 動いている VM のスナップショットはメモリの状態を含み、復元すると動いている状態に戻る。止まっている VM のスナップショットはディスクだけで、復元すると止まった状態に戻る。
- seed ISO はスナップショットに含めない。読み出し専用で、作成のあと変わらないからである。
- スナップショットの名前は、VM の名前と同じ形に限る（[[0003]]）。一つの VM の中で一意とする。
- VM を消すと、そのスナップショットもすべて消す。

## Consequences

- VM の作成は、イメージの取得が済んでいれば数秒で終わる。VM のディスクは、書き込んだぶんしか容量を使わない。
- **保管したイメージは、それを backing file にした VM が一台でも残っているうちは消せない。** 消すとその VM は起動できなくなる（[[0004]]）。
- ドメイン定義のパスはホストのパスなので、vmapi のコンテナにはディスクの置き場をホストと同じパスでマウントする（[[0008]]）。
- 動いている VM の内部スナップショットは、取るあいだ VM を一時停止させる。メモリが大きいほど長い。
- ストレージプールを使わないので、`virsh vol-list` には VM のディスクが出ない。
- 内部スナップショットと seed ISO の組み合わせが libvirt で実際に動くか（読み出し専用の CD-ROM を除外できるか）は、実機で確かめる。動かない場合は、作成の後に seed ISO を外すなどの代案をこの ADR の改訂として決める。
