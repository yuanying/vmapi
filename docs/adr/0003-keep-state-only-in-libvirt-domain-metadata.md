# 0003. 状態は libvirt のドメイン metadata だけに置く

- Date: 2026-10-30
- Status: Accepted

## Context

vmapi は VM ごとに、持ち主（[[0002]]）、払い出した IP、元にしたイメージなど、libvirt の標準の項目に無い情報を覚えておく必要がある。また、vmapi が作った VM と、既存のスクリプトで作った VM とを見分ける必要がある（[[0001]]）。

覚えておく場所の候補は、vmapi が持つデータベース（SQLite など）と、libvirt のドメイン定義の `<metadata>` 要素である。`<metadata>` は名前空間付きの任意の XML を置ける場所で、ドメインと一緒に定義・削除される。

データベースを持つと、libvirt とデータベースの二つが正になり、その食い違い（データベースにあってドメインが無い、その逆）を扱うことになる。`virsh undefine` を人間が直接打てば、すぐに食い違う。

## Decision

**vmapi の状態は libvirt のドメイン metadata だけを正とする。データベースは持たない。**

### metadata に書くもの

vmapi は自分の名前空間（`https://github.com/yuanying/vmapi/metadata/v1`）の要素を一つ、ドメインの `<metadata>` に書く。中身は次のとおり。CPU 数やメモリのように、ドメイン定義そのものから読めるものは書かない。

| 項目 | 内容 |
|---|---|
| 持ち主 | 作成したリクエストの `X-Devbox-User` |
| IP | 払い出した IPv4 アドレス |
| イメージ | 設定のイメージ名と、元にしたファイルの SHA-256（[[0004]]） |
| ディスクの大きさ | 作成のときに指定された GiB |
| 作成日時 | RFC 3339 |

名前空間の末尾の `v1` は metadata の形の版である。形を変えるときは版を上げ、古い版を読めるようにしてから書く側を切り替える。

### vmapi が扱う VM の範囲

**この要素を持つドメインだけが vmapi の VM である。** 持たないドメインは一覧に出さず、名前を指定されても `404` を返し、起動・停止・削除もしない。管理者に対しても同じである。

### 名前

**VM の名前は、ホストの libvirt 全体で一意とし、そのままドメイン名にする。** 持ち主が違っても同じ名前は作れない。すでに同じ名前のドメインがあれば、それが他人の VM でも、vmapi が扱わない既存の VM でも、作成は `409` で拒否する。

名前はホスト名としてもそのまま使うので（[[0005]]）、DNS のラベルとして使える形に限る。英小文字で始まり、英小文字・数字・ハイフンからなり、ハイフンで終わらない、63 文字以下の文字列である。

持ち主の名前をドメイン名に含める案（`<持ち主>-<名前>` など）は採らない。持ち主の名前は token に付けた任意の文字列で、ドメイン名やホスト名に使える形とは限らない。`virsh list` の名前と API の名前とゲストのホスト名が一致しているほうが、人間が libvirt を直接見るときにも迷わない。名前が取られていることが他人に分かるのは、[[0002]] の線引きの目的に照らして許す。

### IP の払い出し

**空いている IP は、そのたびにすべてのドメインの metadata を読んで導く。** 設定の範囲（[[0009]]）のうち、どの VM の metadata にも書かれていない IP が空きである。停止している VM の IP も使用中とみなす。払い出すのは空きのうち最も小さい IP とする。

呼ぶ側は IP を指定できる。指定した IP が範囲の外なら `400`、使用中なら `409` で拒否する。範囲の外を許さないのは、範囲が「既存の VM や LAN の機器と重ならない」ことを保証するための唯一の手段だからである。

範囲に空きが無ければ `409` で拒否する。

### 同時の作成

**作成の「名前と IP を確かめてから define する」までを、プロセス内の一つのロックで直列にする。** vmapi のプロセスは一つしか動かさない（[[0008]]）。イメージの取得（[[0004]]）はロックの外で行い、ロックの中ではドメインの一覧の読み出し、空きの判定、ディスクと seed ISO の作成、define だけを行う。

define の後に start が失敗したら、ドメインを undefine し、作ったファイルを消してからエラーを返す。

## Consequences

- vmapi を再起動しても失うものが無い。起動のときに何かを読み込む必要も無い。
- `virsh undefine` で人間がドメインを消すと、その VM は vmapi からも消え、IP は空きに戻る。ディスクの置き場には VM のファイルが残る。同じ名前の VM を次に作るとき、vmapi はドメインの無い置き場を前回の残りとみなして上書きする。
- 一覧のたびに全ドメインの XML を読むので、ドメインの数に比例して遅くなる。数十台の規模では問題にならない。
- **vmapi のプロセスを二つ動かすと、IP の二重払い出しが起こりうる。** 二つ目を動かす必要が出たら、このロックを libvirt の側に移す（たとえば IP ごとのロックファイルやストレージボリューム）決定を先に行う。
- metadata の無い既存の VM の IP は vmapi には見えない。重ならないことは、設定の範囲の取り方で保証する。
- 持ち主による絞り込み、metadata の無い VM を見せないこと、IP の衝突と同時の作成は、libvirt を偽物に差し替えたテストで確かめる。
