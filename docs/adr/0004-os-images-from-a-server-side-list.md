# 0004. OS イメージはサーバー側の一覧から選ばせる

- Date: 2026-10-30
- Status: Accepted

## Context

VM のディスクは OS の cloud image（Ubuntu の `*-server-cloudimg-amd64.img` など）から作る。呼ぶ側がイメージを指定する方法として、任意の URL を受け取る形と、サーバーが持つ一覧から名前で選ばせる形がある。

任意の URL を受け取ると、vmapi は呼ぶ側の言うままにホストから外へ取りに行き、ホストの root 相当の権限を持つプロセス（[[0008]]）が、出どころの分からないファイルをディスクとして libvirt に渡すことになる。

## Decision

**イメージは設定（[[0009]]）の一覧に、名前・URL・SHA-256 で書く。呼ぶ側は名前で選ぶだけで、URL は受け取らない。**

- **初めて使うときに取得して保管する。** そのイメージで最初に VM を作るとき、vmapi は URL から取得し、SHA-256 が設定と一致したときだけ保管する。一致しなければ保管せず、作成を失敗させる。取得は一時ファイルに書いてから名前を変えるので、途中で失敗しても半端なファイルは残らない。同じイメージの取得が同時に走らないよう、イメージごとにロックを取る。取得は作成のロック（[[0003]]）の外で行う。
- **保管するファイルの名前は SHA-256 にする。** ディスクの置き場の `images/<sha256>.img` に置く。設定の URL とチェックサムを新しいリリースに替えると、次の作成から新しいファイルを取得し、古いファイルは残る。古いイメージから作った VM は、引き続き古いファイルを backing file として使う。
- **VM のディスクは、保管したイメージを backing file にした qcow2 の overlay にする**（[[0006]]）。イメージそのものは書き換えない。
- **チェックサムは固定の値で書く。** Ubuntu の場合、日付の付いたリリースのディレクトリ（`https://cloud-images.ubuntu.com/releases/<コード名>/release-<日付>/`）のイメージを URL にし、同じディレクトリの `SHA256SUMS` から値を取る。`current/` のように中身が変わる URL は、チェックサムがいずれ合わなくなるので使わない。`SHA256SUMS` を実行時に取りに行く形は、URL と同じ出どころのものを照合するだけで、固定の値ほどの意味が無いので採らない。

## Consequences

- 呼ぶ側はイメージの出どころを気にしなくてよい。イメージの一覧は `GET /api/v1/images` で分かる。
- 新しいイメージを使えるようにするのは、設定を書き換えて vmapi を再起動する人間の仕事になる。
- 最初の VM の作成は、イメージの取得のぶん（数百 MB）長くかかる。
- 使われなくなったイメージのファイルは自動では消さない。どの VM も backing file にしていないことを確かめてから、人間が消す。消すための API は今は作らない。
